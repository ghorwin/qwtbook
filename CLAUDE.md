# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A programmer's manual ("Das Qwt Entwicklerhandbuch", 2nd edition) for the [Qwt](https://qwt.sourceforge.io/)
C++/Qt plotting library, focused on the `QwtPlot` component. The book is written in German in AsciiDoc format.
The `code/` directory holds companion Qt/C++ example projects that the text references and that are shipped
for download.

## Repository layout

- `book/de/` — active AsciiDoc source (German). All writing happens here.
- `book/de-alt/` — old MkDocs-based version, no longer maintained.
- `book/adoc_utils/` — shared Python helper scripts (link checker, image prep, date/version fix).
- `book/images/` — chapter-organised assets (one sub-dir per chapter, e.g. `images/LineCurves/`), plus
  `book/fonts/`, `book/css/`.
- `code/` — one qmake project per example/tutorial. `code/qwt-6.3.0/` is a bundled copy of the Qwt source.
- `docs/` — GitHub Pages deploy output, regenerated by `make deploy`. Never edit by hand.

## Building the book

All commands run from `book/de/`. The `Makefile` is the real entry point; `build.sh` just chains its targets.

```bash
make html        # asciidoctor QwtBook.adoc  -> QwtBook.html
make pdf         # asciidoctor-pdf with pdf-theme.yml + ../rouge_theme.rb + ../fonts
make deploy      # copies html/pdf AND ../images ../fonts ../css ../code into ../../docs/
make all         # html + pdf + deploy   (same as ./build.sh)
make clean       # remove QwtBook.html / QwtBook.pdf
./linkcheck.sh   # python3 ../adoc_utils/adoc-link-check.py .
```

`build_html.sh` / `build_pdf.bat` invoke asciidoctor directly with `-a lang=de`; the Makefile omits that
attribute. `make deploy` writes `docs/de/index.html`, `docs/QwtBook_de.pdf`, and refreshes the copied
asset/code trees — this is why `docs/` must not be edited manually.

### Required gems (install once)

```bash
sudo apt install asciidoctor
sudo gem install asciidoctor-pdf --pre
sudo gem install rouge asciidoctor-rouge
```

## Building code examples

Each project under `code/` is a qmake project. `.pro` files probe several install prefixes:
`/usr/local/qwt-6.3.0/` and version-suffixed variants like `/usr/local/qwt-6.3.0-qt-6.10.3/` on Linux,
`C:\qwt-6.3.0\` on Windows.

```bash
cd code/<ProjectName>
qmake && make
```

## AsciiDoc conventions

- Master document is `QwtBook.adoc`; each chapter is a separate file `include::`d from it with
  `leveloffset=+1`. Add a new chapter by creating the file and adding one `include::` line, in reading order.
- `:imagesdir:` is `../images`. Reference images as `image::<Chapter>/<name>.png[pdfwidth=8cm]` — the
  per-chapter sub-directory is part of the path, and `pdfwidth=` / `pdfwidth` hints control PDF sizing while
  CSS handles HTML.
- Image filenames must contain at most one `.`. Helper `../adoc_utils/adoc-image-prep.py <html|pdf> .`
  swaps in `-print`-suffixed image variants for the PDF build; run it manually when needed.
- Section anchors are written as `[[sec:name]]` alone on their own line, immediately followed by the
  section header (`== ...`) or a `.Title` line. Reference them with `<<sec:name>>`. `linkcheck.sh` parses
  these strictly (anchor alone on line, label taken from the next line) and warns on missing or
  number-leading labels — keep to that shape or the check breaks.
- Source blocks: both `[source,c++]` and `[source,cpp]` appear in the tree; prefer `[source,cpp]` for new
  blocks. Highlighting is rouge (`:source-highlighter: rouge`, `:rouge-style: custom`).
- Qwt class names (`QwtPlot`, `QwtDial`, …) are always inline code.
- German admonition captions are configured in `QwtBook.adoc` (Achtung, Beispiel, Abbildung, Tabelle).
